前端开发提示词：鲜果记 - 用户端小程序（1:1 复刻原型图）
一、项目目标
基于 Stitch 导出的 HTML + PNG 原型图（位于项目根目录 /prototypes/ 文件夹下，每个页面对应一个 .html 文件和一张 .png 截图），1:1 高保真复刻为可运行的 uni-app 跨端小程序项目。最终编译目标为微信小程序，开发期间允许在 H5 端预览。
1:1 的具体含义：

颜色值、字号、行高、字重、间距、圆角、阴影必须严格匹配原型
布局结构、元素层级、相对位置必须一致
图标、按钮形态、Tab 高亮、状态切换的视觉表现一致
唯一允许的差异：将 Web 端 HTML 控件替换为 uni-app 等价组件（见下方"转换规则"）

二、技术栈

框架：uni-app（Vue 3 + Composition API + <script setup>）
语言：TypeScript
构建工具：Vite
包管理：pnpm
状态管理：Pinia
样式预处理：SCSS
UI 组件库：wot-design-uni（Vue3 原生、风格干净，适合品质感场景）
HTTP 请求：uni.request 二次封装，统一拦截器
图标：iconfont 引入 SVG 字体（从原型图中提取所需图标，建立项目专属图标库）
Mock 数据：本地 JSON 文件 + 延迟模拟接口，路径 src/mock/

五、Stitch HTML → uni-app 转换规则（关键）
Stitch 导出的 HTML 是 Web 标准代码，不能直接搬到 uni-app，需要按以下规则转换：
Stitch HTML 中的元素uni-app 中对应写法<div><view><span>、纯文本节点<text><img src="..."><image src="..." mode="aspectFill" /><button><button> 或自定义 <view> 模拟（小程序原生 button 有边框，建议自定义）<input><input>（注意 v-model 绑定）<textarea><textarea><a href> 跳转uni.navigateTo({ url: '...' })position: fixeduni-app 中 <view> 也支持，但底部 Tab 占位需用 safe-area-inset-bottomCSS :hover小程序无 hover，使用 :active 或 hover-class 属性localStorageuni.setStorageSync / uni.getStorageSync字体 px 单位全部转 rpx（×2）长列表改用 <scroll-view> 或分页加载，禁止一次性渲染上百条display: grid小程序支持，但建议复杂网格用 flex 实现以确保兼容
禁止行为：

不要直接复制 HTML 中的 <div class="..."> 写法
不要保留 Stitch 生成的随机 class 名（如 css-1a2b3c），改用语义化 BEM 命名
不要复制 Tailwind utility classes（如果 Stitch 用了），改写为 SCSS

六、复刻工作流（每个页面执行）
对 /prototypes/ 下每个页面，按以下顺序处理：

打开 PNG 截图——肉眼观察整体布局、颜色、间距、特殊视觉细节
打开同名 HTML 文件——查看 DOM 结构与 CSS 样式作为骨架参考
提取设计 Token——校验 HTML 中的颜色 / 字号 / 间距是否与项目 variables.scss 一致；不一致以 variables.scss 为准
拆分组件——识别页面中可复用的部分（如商品卡片、价格标签、空状态），提到 components/ 下
编写 Vue SFC——按 uni-app 规范实现，使用转换规则
接入 Mock 数据——从 mock/ 目录读取对应 JSON
逐项对照 PNG 截图自检——使用下方"1:1 验收清单"

七、Mock 数据要求
在 src/mock/ 下建立以下文件，提供仿真数据让页面看起来"像真的"：

reviews.json：20+ 条评价（含图、不同星级）

商品图、用户头像可使用占位图服务（如 https://picsum.photos/）或本地 static/ 下的占位 PNG。

九、全局规范
命名：

文件名 kebab-case（goods-card.vue）
组件名 PascalCase（<GoodsCard />）
CSS 类名 BEM（.goods-card__title--active）
接口字段保持后端风格（snake_case 或 camelCase 与后端约定一致）

TypeScript：

所有组件 props、emit、store state、API 响应必须有完整类型定义
类型集中在 src/types/ 下，按模块拆分

性能：

列表页使用 <scroll-view> + 分页加载（每页 20 条）
图片使用懒加载（lazy-load 属性）
长列表 v-for 必须有稳定的 key（不要用 index）
避免在模板里写复杂表达式，挪到 computed

交互细节（容易被忽略但影响 1:1 还原度）：

按钮点击需有 :active 反馈（透明度 0.7 或缩放 0.97）
加入购物车时需有"飞入购物车"动画或至少有 Toast 反馈
下拉刷新使用 uni-app 原生 onPullDownRefresh
加载中状态使用骨架屏，不要用单独的 Loading 圈
Tab 切换、规格选择、勾选状态必须有过渡动画（150-250ms）

安全区适配：

iOS 全面屏底部需预留 safe-area-inset-bottom
顶部状态栏使用 getSystemInfoSync() 获取高度

十、1:1 验收清单（每页完成后逐项核对）

 所有颜色取自 variables.scss，无硬编码 hex
 字号、字重、行高与原型一致

 图标风格统一（线性 / 描边粗细一致）

 TypeScript 无 any 类型、无报错
 微信开发者工具中预览正常，无控制台报错

十一、不要做的事

❌ 不要自行发挥设计——遇到原型未明确的细节，先在代码注释中标注 // TODO: 等待设计确认，不要"看起来差不多就行"
❌ 不要把 Stitch HTML 中的 inline style 直接复制——必须改为 SCSS 类
❌ 不要使用未在 variables.scss 中定义的颜色、字号、间距
❌ 不要省略空状态和加载状态——这些占了体验的 30%
❌ 不要为了赶进度跳过 TypeScript 类型——后期补反而更慢
❌ 不要在一个 SFC 里塞 500 行以上代码——超过就拆组件
